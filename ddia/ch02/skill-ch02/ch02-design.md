> 按概念切学习单元，不按目录标题切。共 12 个内容单元 + U0 开场总述，总时长估计约 45–50 分钟（按第 1 章实测约 15 秒/要点、189 个要点估算，以实际 TTS 为准；PLAN.md 的 885 秒估计不可信，第 1 章 skill 版最后 37 分 40 秒，远超 PLAN 估计）。

## 单元 U2：同一份简历，两种长相（样片单元）

- 钩子：一份简历，拆成六张表和一个 JSON，哪个更像它？
- 学习目标（新手测试题）：1. 什么是对象关系失配（impedance mismatch）？ORM 能彻底解决它吗？2. 同一份简历在关系模型和 JSON 文档里分别长什么样？3. 为什么 JSON 表示取一份档案只要一次查询？
- 常见误区：JSON 只是“把表拼成一个大字符串”；ORM 让两种模型的区别消失了；文档模型没有缺点。
- 核心画面 / 主线例子：Figure 2-1 按原图复现的六张表（Bill Gates 档案，user_id 251）↔ Example 2-1 的 JSON 文档，同一份简历两种长相来回切换；主线例子 Bill Gates 档案在本单元首次出现，U3、U5、U12 回扣。
- 深度演示：局部性对比——关系表示取档案要六次查询（按 user_id 查每张表）或一次 messy 多路 join，JSON 表示一次查询就够；一对多关系显式化成树（Figure 2-2）。
- 叙事弧：钩子（两种长相）→ 直觉（对象图 vs 表，中间隔翻译层）→ 机制（拆成六张表：外键；合回一个 JSON：嵌套）→ 证据（Figure 2-1 六张表、Example 2-1 JSON、局部性对比）→ 边界（JSON 的问题留到第 4 章、SQL 后来也加了 JSON/XML 支持）→ 回扣（自包含文档用 JSON 更合适）。

## 单元 U4：历史重演

- 常见误区：新技术一定比旧技术先进；文档库是全新的发明，和过去没关系。
