## 方法备注（供后续单元参考）

- 混流时 `-shortest` 会取三路流里最短的——字幕流末条止于 225.606s 时会截掉视频尾部；
  音频短于视频时应去掉 `-shortest`（或先确认字幕流不是最短流）。（r1 教训，r2 沿用。）
- Manim 长场景实测时长可能比时间轴长约 0.4s（本例 monitor +0.389s），拼接前务必 ffprobe 核对每段，
  超差且尾部静态时可在暂存区截尾，但须在 review 里记下并追根因。
- **渲染锁死锁判定（协调方修正，U2-r4 实测发现）：**只查 render.mjs / vite / Chrome 进程是不够的——
  Manim 渲染是 python 进程，不在那三类里。U2-r4 等锁时曾三次把 U7 的锁误判为死锁，
  实际 U7 的 Manim 渲染（python 进程）还活着在写 partial 文件。
  只有同时确认 render.mjs、vite、Chrome **以及 Manim/python 渲染进程**全都不存在，
  且 owner PID 已死、对应产物完整，才能清掉死锁；否则继续等。本轮等锁时已按此规则检查。
- **修 P1 可能暴露潜伏问题：**b12 的 openCount 标签与点阵重叠在 r1 里不可见（整个容器 opacity=0），
  容器淡入后才显现。修“不可见”类问题后，要对该拍做全时段定向抽帧复核，不能只看修的那一行是否生效。
- **复用段也要抽帧复核：**本轮 amp 段的标签重叠（N-1）就是复用复核时发现的；
  r1 只核对了读数，漏掉了重叠。复用不等于免检。
- 联系表务必按数字顺序拼：本轮用零填充命名（01–32.png）再拼表，不用 `ffmpeg -pattern_type glob` 直接拼（会按字典序拼错）。
