## 验证：P1 1-1 为什么没修好（根因）

- 渲染成功：mc2 104.67s、mc1 101.07s，两次均 exit 0、无 beat 超时警告、无 page error；成片 `u2.mp4` 205.34s（-shortest 收尾差 0.35s，与 r1 同模式）。
- 2fps 法重测（阈值 >8 灰阶、>0.02% 像素）：目标拍尾部静止几乎未变——b9 5.62s、b11 6.07s、b19 4.50s、b21 5.07s、b22 4.69s、b23 5.10s、b29 3.40s、b30 3.17s、b32 5.25s、b3 4.10s；**全片尾部静止合计 133.4s（r1：134.3s）**。
- 逐帧 diff 证实：b9 的动作在拍内前 ~2s 就结束了（44–45.5s 有变化，之后全静止）；b11 只有 57–59.5s 有变化。
- **根因**：`sequence(delay, ...)` 只错开各任务的**起跑时间**，不等前一任务完成（`@motion-canvas/core/lib/flow/sequence.d.ts` 原文："The function doesn't wait until the previous task in the sequence has finished. Once the delay has passed, the next task will start even if the previous is still running."）。r2 写的 `sequence(0, 淡入 2.2s, 淡入 2.2s, 缩放 1.8s)` 是四项**并行**跑，最长 2.2s 就全结束了——“拉长”根本没拉长。要“做完再做下一步”必须用 `chain()`（同目录 `chain.d.ts`："Run tasks one after another"）。U5 模板 `u5-mc1.tsx:227` 的注释已写明此陷阱，r1/r2 漏读了。
- **r3 方案**：10 个目标拍（b3、b9、b11、b19、b21、b22、b23、b29、b32，另 b30 已是并行长动画不动）改 `chain()` 真串行；音频、timeline、分镜内容一字不动。
