### E1. v1.7.1 补丁：渲染成功后自动验证解码输出
- **问题**：QA 是对直播页面采样、不看落盘文件；渲染报成功也不等于文件可用。本轮单元制作阶段出现**两例严格触发**（QA 报 0 error 但落盘文件损坏）：
  - U8 r3 / u8-mc3：QA 0 error / 8 warn，落盘只有 18.93s / 568 帧（预期 85.00s / 2550 帧），全片解码还干净——只比时长/帧数才看得出。直接重渲已修复（85.00s / 2550 帧）。
  - U4 r3 / u4-mc1：QA 0 error / 19 warn，落盘截断为 16.17s / 485 帧（预期 132.67s / ~3980 帧），解码干净。更暴露了新口子：截断文件落盘时指纹也被更新了，第一次重渲因指纹新鲜被跳过——删指纹强制重渲后才恢复（132.67s / 3980 帧）。
  - 同类但非严格触发：U4 mc3 截断 8.97s（QA 报了 1 error）；U9 r2 mc1 渲染失败（exit 1）覆盖了干净的 59.0s 文件成 37.8s 截断文件；U0 r2 超时截断 15.47s；探针渲染写坏 u2-mc1（3138 行解码错误）；48 字节空头文件多例。证据全在 `v171-observations.md`。
- **方案**：skill v1.7.0 → v1.7.1 小补丁（同 PR #11 的 v1.6.1 路子）。钩子只挂在 `qa_chapter.py` 一个口子上：每个场景渲完，顺手对刚落盘的文件做一次完整解码加 ffprobe 核对（沿用装配预检的容差：容器和视频轨时长差 0.5 秒内、帧数差 2 帧内），解不出来就让那个场景直接失败——这样上面两例在落盘那一刻就会被拦住，根本拿不到通过的指纹。
- **代价**：每个场景多一次解码，几秒钟，相对几分钟的渲染可以忽略。
- **验证**：先加 qa_selftest 用例（截断/双 moov 的坏文件必须失败、好文件必须通过），重跑 qa_selftest（v1.10.0 基线 63/63），再开 PR 给你合、重装 skill、同步渲染脚本（同 PR #13 流程）。
