## 2. 反查原文（§3.12–§3.13，book pp.99–101）

逐条核对本轮新增机制表述的书上依据；书上没有的，明确标为“推论/演示措辞”，不冒充书上原话：

- **F1/F2（m9）**：§3.12——“date_key 作第一排序键，查上个月时优化器只扫上个月的行”。“按边界值一比就知道从哪一段开始”是对“optimizer scans only last month's rows”的演示措辞；“140101、140102 只是日期码，当两个月份的示意”——日期码本身是演示表的示意值，屏上已明说“只是示意”，不冒充书上数据。
- **F3（m16）**：§3.12——“数据本来就复制到多台机器防故障；同一份数据按不同排法存”。“每台机器存一份，排法各不相同，这台坏了，另一台还有同款副本”与书一致；✗ 标为“这台坏了”是演示示意。
- **F4（m26c）**：书上**没有**“每种排法各有一份写缓冲”的说法。本轮措辞“一种排法，单独并一次，几份排法就并几遍，读的那份才跟得上”是直接推论（每种排法各有一份读用的列文件，不并进去读的那份就旧了），不冒充书上原话。
- **F5（m22）**：“B 树前面第四站讲过”——U4 第四站，B 树，站牌“第四站，B 树。”属实；“一页里改一格值，就地盖写就行”是对行存原地更新的通俗说法，与 §3.13“B-tree-style update-in-place”一致。
- **F6（m24）**：“前面第三站讲过的 LSM 树”——U3 第三站，LSM 树，站牌“第三站，LSM 树。”属实；“写先进内存，攒够再批量写盘”即 §3.13-3（all writes go first to an in-memory store … merged … written to new files in bulk）。
- **F7（m25/m26）**：① 三笔来历“新来了三笔写”是演示措辞（书上无这三笔）；② 为何走缓冲——§3.13-2（中间插行要重写全部列文件）+ §3.13-3（攒够再批量合并），“下一笔可能落在中间，一插行就要重写全部列文件，所以先攒着”有书可依；③ 触发条件“攒到一千笔，或攒到几兆，二者任一就合并”——书上**无** 1000/几兆这两个数，是示意量级（与 §3.3 memtable“通常几 MB”量级一致），措辞已去歧义（“二者任一”）；④ 旧文件去向“旧的列文件被新文件替掉”——§3.13-3“written to new files in bulk”的直接表述。
- **F8（m27）**：§3.14 聚合（COUNT/SUM/AVG/MIN/MAX）+ 物化聚合缓存计数/求和。“新总数是旧总数加这段时间攒下的次数”是对“合并时加总”的无歧义表述；“键 ≈ 视频名，计数 ≈ 播放次数”是类比桥接（书上无猫视频例子，是演示措辞）。
- **F9（m28b/m28c）**：书上**没有**行身份识别机制（§3.13-2 只说行靠“列内的位置”识别）。本轮按任务处方改成不依赖“认出同一行”的说法：m28b 恢复 r5 原文，新增 m28b2“内存里这笔写的是同一行，数量 2 改成 9。”（只陈述对应关系，不编造匹配机制）；m28c“查询时先跳过它，下次合并时再把它清掉”——“下次合并清理”是 U3 LSM 合并规则（“只留最新值”）的复用，§3.13 未明说，属演示口径，不冒充书上原话。
