## 反查原文（§3.6，书 p85–87，PDF p107–109；§3.4 B 树按键排序）

原书依据：DDIA §3.6 "Other Indexing Structures"；r9 已核对的机制表述本轮未改，结论继承 r9。仅核对 r10 新增/改动的机制表述：

- **P2-2 两级映射（值是行号列表，行号再指到槽）**：书明说值可以是“匹配行标识符列表”（a list of matching row identifiers），堆文件做法是“每个索引只记一个指向堆文件的位置”（each index just references a location in the heap file）。本片的口径（r8 已定：行号是身份、槽是位置）下，两级映射是这两句的合写：值里记行号，行号再指到槽；槽变了，索引里记的槽就得改——与 f22“更新所有索引，让它们指向新位置”一致。✓
- **P2-4 行号列表就是“引用”**：书明说值的两种可能之一是“存在别处的行的引用”（a reference to the row stored elsewhere），堆文件即行存别处的地方；行号列表指着堆文件里的行，正是该种可能在本片演示里的形态。✓
- **P2-7 切换点**：堆文件情形书明说“要么更新所有索引指向新位置，要么留转发指针”；InnoDB 情形书明说二级索引记主键“而不是堆文件位置”。规则句是两处原文的对照总结：记位置的搬家得改，记主键的不用改。✓
- **P2-8 行号只是代号**：书 p85 "A primary key uniquely identifies one row"；行号是视频给行的代号，不是主键本身——本句只明说演示口径，未给行 19 编造主键值；“页里行按主键排着”是 r8 已核对的 f24f 原文（页裂依据），本轮未改。✓
- **P2-9 聚集键（推论）**：书只说 InnoDB“二级索引引用主键（而不是堆文件位置）”与 SQL Server“每表可指定一个聚集索引”[31][32]，**未明说聚集索引不是主键时二级索引记什么**。本轮 f24d2 新句“二级索引记的是聚集键”与“聚集键变了才要改，没变就不用改”是按聚集索引定义（行直接存在聚集索引里，二级索引须指到行）+ InnoDB 类比的推论，符合 SQL Server 的实际做法（非聚集索引存聚集键），但书上无此原话——**记为推论/演示措辞，不冒充书上原话**。✓（标注如此）
