## 新手测试（自测模拟，非独立实测）

方法：仅凭成片（画面 + 旁白，不看书与清单），回答设计文档的三个学习目标问题。**以下为自测模拟，不是独立实测。**

1. db_set / db_get 是怎么存、怎么找的？为什么找是 O(n)？
   答：db_set 把“键，值”追加到 database 文本文件末尾；db_get 用 grep 找该键的行、去掉键前缀、取最后一次出现（旧值还在文件里）。找是 O(n)，因为每次查都要从头到尾扫整个文件，记录翻倍、查找时间翻倍（4 行/8 行对比）。—— 答出 ✓
2. 什么是索引？它从哪来、要付什么代价？
   答：索引是放在旁边的额外元数据、路标，告诉你数据在第几行；它从主数据派生出来，可以增删、不影响数据库内容；代价是每次写数据索引也得跟着更新，维护有开销。—— 答出 ✓
3. 为什么说“写很难比追加更快”？
   答：追加到文件末尾是最简单的写操作（“只追加：一路直行”），任何索引都会让写多拐一道弯（更新索引），所以写很难比单纯追加更快。—— 答出 ✓

设计里的两个常见误区均被成片正面纠正：索引不是免费自带的（b19a 手工选、b16 维护开销）、读写不能同时变快（b18 天平）。

结论：3/3 通过（自测模拟）。

## 过程记录：u1-mc2 渲染失败根因（供后续单元参考）

u1-mc2 曾连续 3 次在渲染开始约 4–6s 后失败（`[render] finished: 1`，mc-logger 报错无消息体）。二分定位到 b20–b22 后排除字形嫌疑（'≠' → '!=' 仍失败），最终查 `beats.ts` 的 `cueTime()`：`at()` 短语不在当拍旁白里时直接 `throw new Error`；渲染前的 recalculate 快进整条时间轴，于是错误在拍首就触发。根因是 **b20 的 `at('写一半的记录', …)` 与实际旁白“写了一半的记录”差一个“了”字**（分镜稿沿用旧写法，TTS 定稿改过措辞）。修复为 `at('写了一半的记录', …)` 后一次通过。教训：`at()` 短语必须以 `timeline/*.json`（TTS 定稿）为准核对，而不是分镜稿；`lint_scenes.py` 不检查这一点。已全量核对两场景共 55 个 `at()` 短语，全部通过。
