## 新手测试（只给旁白文本 + 联系表，假装没读过这一章）

design.md 的 U3 学习目标 3 题，逐题作答如下（模拟说明：审查人已读过原文，本测试为按“只凭旁白文本 + 联系表”约束的模拟作答，答案均可在 beats.md 与 sheet.png 中直接找到）：

1. **为什么一块盘能用 10–50 年，一万块盘却每天坏一块？**——答：一块盘的平均无故障时间（MTTF）是 10–50 年；一万块盘放在一起，失效率相加，平均每天就有一块死，这是数量级的力量（b1/b3/b4 + 方阵画面）。**答对**。
2. **硬件故障和软件错误有什么根本不同？**——答：硬件故障大多随机、互相独立，一块盘坏不代表另一块也要坏（b16）；软件错误是系统性的、跨节点相关，所有节点同一时刻一起变红，比硬件故障更容易酿成大祸（b18）。**答对，但有保留**：b16 画面里三个红点排成一列，新手可能从画面得出“硬件故障也成列坏”的错误印象——这正是问题 1-1。
3. **大型互联网服务宕机的首要原因是什么？运维团队有哪几招应对人为错误？**——答：首要原因是运维配错了配置，硬件故障只占 10–25%（b29/b30）；六招是好设计、沙盒、彻底测试、快速恢复、详细监控、管理培训（b31–b43）。**答对，但有保留**：第一招“好设计”靠什么实现（好抽象 / API / 管理界面）在旁白和画面里都没出现——这正是问题 1-5。
