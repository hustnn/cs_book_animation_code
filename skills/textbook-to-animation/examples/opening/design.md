# 存储与检索 教学设计（示例 · 只含开篇单元）

> 示例取自一本数据系统教材的第 3 章。整章的 design.md 里，开篇单元排在第一个，其余单元（U1–U15）接在后面；
> 这份只放开篇单元，所以 `check_design.py` 不查“路线图覆盖全部单元”（写全了就会查：漏一个、多一个、顺序不对都是 FAIL）。
> 路线图的站名、单元标题和 `scenes/chapter.ts` 一一对应：画面从 chapter.ts 取，设计从这里取，改一处就改两处。

## 单元 U0：开篇

- P0 机制（≤ 3）：无（开篇）
- 章标题：第 3 章 存储与检索（Storage and Retrieval）
- 一句话主旨：数据库就做两件事，存下来、找回来；怎么存决定了能多快找回来，而让读变快的办法（比如索引）往往让写变慢——这一章讲几种存法和各自的代价。
- 和上一章的关系：上一章讲数据长什么样（数据模型）；这一章往下走一层，看数据库在磁盘上怎么放、怎么找（存储引擎）。
- 钩子：存进去的东西，怎么才能又快又准地找回来？
- 学习目标（新手测试题）：
  1. 这一章分几部分？每部分回答什么问题？
  2. 给数据建索引，对读和写各有什么影响？
  3. 这一章和上一章是什么关系？
- 核心画面：一条有身份的数据（handful:44662）在“你的程序”和“数据库”之间走一个来回；写入 / 查询两根计量条（示意）；
  两层叠起来的“数据模型 / 存储引擎”；全章路线图（之后每个单元的站牌、末单元的收束都用同一张图）。
- 开篇拍：标题 o1；主旨 o2–o3；和上一章 o4；路线图 o5–o8；下一站 o9
- 不在开篇里讲的：任何机制的细节（日志怎么追加、树怎么分裂）都留给对应的单元；开篇只回答“这章讲什么、分几部分、从哪开始”。
