# 示例：整章开篇（章标题 → 这章讲什么 → 路线图 → 下一站）

一章的第一个单元。观众打开视频，先看到“第 3 章 · 存储与检索”，再用一分钟知道这一章讲什么、分几部分、从哪开始，
然后才进入第一个机制。没有这一段，开头就是突兀地抛一个问题或直接讲机制；十几个单元连着放，观众也不知道自己在哪。

一个场景、9 拍、约 70 秒（配音是临时的，用的是 macOS 自带的语音）。原书第 3 章，16 个单元。

## 先看什么

1. `frames/`：7 张关键帧，按拍号排。
2. `design.md`：开篇单元怎么写——章标题、一句话主旨、和上一章的关系、开篇拍、`### 路线图` 表。`check_design.py` 按它检查。
3. `beats.md`：o1–o9，每拍的旁白、跟着哪个词做什么、用的哪个组件。
4. `scenes/opening-chapter.tsx`：场景；`scenes/chapter.ts`：章数据（工程里放在 `src/lib/chapter.ts`，所有场景共用）。
5. 渲染出来看：`python <skill>/scripts/examples.py render opening --project <你的 motion-canvas 工程>`。

## 结构（顺序固定）

| 段 | 拍 | 做什么 | 组件 |
|---|---|---|---|
| 标题 | o1 | “第 3 章”、章名、原书章名；旁白念出“第三章，存储与检索”；演示拍留 1.2 秒 | `ChapterTitle.enter()` |
| 这章讲什么 | o2–o3 | 一条有身份的数据在程序和数据库之间走一个来回（存下来、找回来）；两根计量条：建了索引，查询变快、写入变慢（标“示意”） | `ChapterTitle.toHeader()`、`KV`、`Meter`、`tag` |
| 和上一章的关系 | o4 | “数据模型（上一章）”在上，“存储引擎（本章）”在下，往下走一层 | Rect + Txt |
| 路线图 | o5–o8 | 一部分一拍逐行点亮：部分名、它回答的问题、一串站；念到哪一站，哪一站闪一下 | `Roadmap.showRow()`、`pulseStop()` |
| 下一站 | o9 | 其余各行压暗，第一站变黄、套圈、标“下一站” | `Roadmap.focus()` |

开篇只回答“这章讲什么、分几部分、从哪开始”，不讲机制细节。但它也不是一叠文字卡：每一拍都有东西在动。

## 之后的每个单元

- 第一拍是**站牌**：`UnitTitle(CHAPTER, 'u3')` 写出“存储与检索 · 第 3 站 / 共 15 站”、单元标题和迷你路线条，旁白念“第三站：排好序的段”；
  下一拍开头 `toHeader()` 收成左上角页眉。样本：`examples/lsm/` 的 w0。
- **末单元**（小结）用同一张 `Roadmap`，`complete()` 全部点亮，逐部分回收一句结论。

## 检查

- `check_design.py design.md --beats-json beats.json`：开篇单元排第一；章标题、一句话主旨、开篇拍都写了；路线图 2–4 个部分、
  覆盖全部单元且顺序一致；标题拍是第一拍、念出了章名；开篇估计超过 90 秒记 WARN。
- `lint_scenes.py`：播某个单元第一拍的场景没有 `UnitTitle` / `ChapterTitle` 记 error；一整章没有开篇（`ChapterTitle` + `Roadmap`）记 error。
