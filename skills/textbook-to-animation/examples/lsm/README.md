# 示例：LSM 树（完整单元，设计 → 分镜 → 场景 → 自检）

一个按本 skill 全流程做出来的单元：原文“SSTable 与 LSM 树”一节，做成 3 个场景、42 拍、约 4 分 16 秒。
它是“机制讲透”和“图式”两件事的参照样本：做存储、索引、消息、复制这类“数据在系统里怎么变”的单元时，先看这里。

## 先看什么

1. `frames/`：13 张关键帧（文件名就是拍号和图式），一分钟看完整体画面。
2. `design.md`：教学设计——P0 机制、带 [走查] 的学习目标、图式的四个问题、每个机制的走查表、深度延伸及依据。
   **自己的 design.md 照这个结构写**，`scripts/check_design.py` 按同样的结构检查。
3. `beats.md`：分镜——每拍的旁白、跟着旁白的哪个词做什么动作、屏幕文字、用的是哪种图式。
4. `scenes/`：场景代码（`lsm-stage.ts` 是三个场景共用的全景图坐标）。
5. 渲染出来看：`python <skill>/scripts/examples.py render lsm --project <你的 motion-canvas 工程>`
   （临时装进工程、带 QA 渲染、结束后清理；成片在工程的 `output/lsm-*.mp4`）。

## 深度：原文写了什么，视频讲到哪

| 机制 | 原文 | 视频 |
|---|---|---|
| 写入路径 | 写进内存里的平衡树（memtable）；满了写成磁盘上的 SSTable；另有一份日志用于崩溃恢复 | 一个个真实的键值块走完全程：追加日志 → 有序插入（其余让位）→ 覆盖 → 满了冻结 → 顺序刷盘 → 丢日志 |
| 读取路径 | 先查 memtable，再从新到旧查各段；布隆过滤器可以省掉不存在的键的读 | 计数器数清每次磁盘读；推镜头看稀疏索引 → 块；**延伸**：布隆过滤器的比特位、哈希、误判和约 1% 的量级 |
| 压缩合并 | 两种策略的名字和一句话描述；谁用哪种；按层“更增量、占空间少” | 按大小先用真实数据合并一次（同键只留最新）再抽象成三级；按层画在一根键轴上，重叠、只动一小块、每层最多查一段都直接看得出来；**延伸**：读 / 空间 / 写的取舍 |

延伸的每一条都在 `design.md` 的“深度延伸”表里写了依据，画面上标“延伸 · 原文之外”或“示意”。
旧版这一段的问题（“小段并进大段”的空框 0.45 秒一闪而过、两种策略合计 15 秒）就是这个示例要替换掉的。

## 自检结果（`examples.py check` 会重跑）

- 渲染 QA：0 error，移动过快 0 条；lint 门槛全部通过，跨 `at()` 同对象补间 0 处。
- 读取场景的 warn 几乎都来自剖面放大时虚化退后的全景（不透明度 < 0.6，按叠化记 warn），是有意的。
- 配音是临时的 macOS 合成音（只为拿到真实时长），`timeline.json` 就是用它生成的；本地成片 `lsm-sample.mp4`、`audio/` 不入库。

## 做的过程中踩过的坑（已写进规则）

1. Motion Canvas 的 `Camera` 组件让 QA 看不到里面的内容 → 用 `Cam` 缩放 world 节点。
2. 推镜头后镜头外的文字被判出画 → 先淡出。
3. 同一个块的连续移动拆进几个 `at()` → 块来回抽动（lint 现在会报 warn）。
4. 竖向引导线压字 → 先 add 线再 add 块。
5. `qa-ignore-*` key 重复 → 自动加序号。
6. 复制块先显形再出发 → 和原块叠在一起；出发时才显形。
7. 一拍最后一个 cue 之后还排了几段动作 → 超时；用 `at(…, lead)` 提前或挪到前面的 cue。
8. 新的“移动过快”检查第一次跑报了 2 条（查询块最后两跳 0.5s；块还没落位整组就淡出）→ 改成 0.6s、淡出推后 0.3s。

## 已知不足

- 按大小合并抽象成三级后，中段、大段是只表示大小的框（这时它们确实只代表“更大的段”，前面已经用真实数据演过一次）。
- 第 0 层合并进第 1 层这一步没演。
- 读取场景底部三行过滤器格子较小（20px），全景下靠红框位置和右侧“不在”标签读。
