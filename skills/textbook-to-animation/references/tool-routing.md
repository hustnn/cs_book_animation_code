# 工具路由：Motion Canvas 还是 Manim

## 判断的问题

1. 这一拍的主角是**“东西在系统里怎么流动、怎么变化”**（节点、消息、表、队列、状态）吗？→ **Motion Canvas**
2. 这一拍的主角是**“一个量怎样随另一个量变化”**，或者一个数学论证（曲线、分布、概率、公式、集合）吗？→ **Manim**
3. 两者都有？→ 拆成两拍：MC 先演机制，Manim 再出定量结论。或者干脆在 MC 里画一条简单曲线（MC 的 `Line` 加 `points` 补间就够了），
   避免一拍之内切换工具。

## 对照表

| 内容 | 推荐 | 理由 |
|---|---|---|
| 请求流、复制、分区、扇出、拓扑 | MC | 信号驱动的组件、生成器时间轴，适合多对象协同 |
| 表、行、索引、日志的结构变换 | MC | 布局（Layout）和文本组件好用 |
| 状态机、协议时序图 | MC | 箭头和节点高亮 |
| 函数曲线、利用率–延迟、扩缩阶梯 | Manim | `Axes`、`ValueTracker`、`always_redraw` |
| 分布、直方图、百分位、排序动画 | Manim | 大量同质对象 + 坐标精确 |
| 概率放大 1−(1−p)ᴺ、生日问题类 | Manim | 曲线加读数联动 |
| quorum 交集、集合论证、不等式 | Manim | 集合和几何直观 |
| 推导规则、逻辑推理（如 Datalog 由事实推出新事实） | **MC** | 本质是结构在生长，不是数学曲线；容易被误分给 Manim |
| 代码 / SQL 逐行高亮 | MC | `Code` 组件（2d 包）支持选区高亮 |
| 章首引言、单元小结 | MC 文字卡（`assets/motion-canvas/card.tsx`） | ≤ 3 行，配旁白，每单元最多 1 张 |

## 衔接规则

- **配色语义全书统一。** 比如蓝 = 正常请求，红 = 慢或故障，绿 = 已同步或成功，黄 = 强调或阈值，紫 = 元信息。
  MC 和 Manim 引用同一份色值（`assets/motion-canvas/theme.ts` 和 `assets/manim/theme.py` 要保持同步）。
- **同一个数字在两种工具里写法一致**（单位、千分位、是否带空格）。
- **转场：** 从 MC 切到 Manim 时，最后一帧和第一帧保持同一个主体（比如 MC 里 7 个后端条形 → Manim 第一帧也是这 7 根条形，再变成坐标轴）。
- 分辨率、帧率、背景色一致（1280×720、30fps、`#0F172A`），否则拼接时会闪。
