## 1. 一轮的完整流程

```
生成 rN ──► 建快照 rounds/<unit>/rN/ ──► 四道审查 + 与 r(N-1) 对比 ──► 写 review.md
                                                  │
                    ┌─────────────────────────────┴───────────────────────────┐
              有 P0 / P1                                                  没有 P0 / P1
                    │                                                         │
      改 inventory / 分镜 / 代码                                     交给用户验收（第 6 节）
                    │                                              │                  │
               生成 r(N+1) ◄────── 用户提了意见（分级后作为下一轮输入）      用户确认满意
                                                                                  │
                                                                       写 FINAL，单元定稿
```

- 每一轮都是完整的：四道审查全部重跑，包括上一轮已经通过的项，因为修改可能引入新问题。
- 已经存好的轮次目录不再修改。修改一律进入下一轮；要回退时，从对应轮次的快照恢复。
- 第 1 轮通常问题最多，不要因为问题多就跳过某道审查；也不要在自动审查还有 P0/P1 时就交给用户。

## 2. 准备：建快照

在 `rounds/<unit>/rN/` 里放好：

| 文件 | 怎么得到 |
|---|---|
| `beats.md`、`timeline.json` | 复制本轮实际使用的版本 |
| `<unit>.mp4` | 本轮成片（拼接混音后的那份） |
| `frames/`、`sheet-NN.png`、`frames.md`、`freeze.json` | `python <skill>/scripts/sample_frames.py <unit>.mp4 --timeline timeline.json -o .`：每拍 5 帧全分辨率（拍首 +0.15s、25%、50%、75%、拍末 −0.15s）、一行一拍的联系表（每帧标拍号和时间），以及每拍最长定格。单个场景的视频加 `--scene <场景>.tsx`。深色背景下 blackdetect 会误报，不要用它判断黑帧 |
| `lint.txt` | `python <skill>/scripts/lint_scenes.py <场景目录> --manim <manim 目录> --timeline-dir <chapter>/timeline --narration <chapter> > lint.txt` |
| `qa.md` | `python <skill>/scripts/qa_chapter.py --project motion-canvas --dir src/scenes/<chapter> --md rounds/<unit>/rN/qa.md`（各场景的原始报告在 `motion-canvas/output/<场景>.qa.json`） |
| `review.md` | 本轮审查完成后写（模板见第 7 节） |

同时打开：inventory.md（含图表处置表）、design.md，以及**这个单元覆盖的原文页和原图图片**（反查原文要用）。

## 3. 四道审查清单

### 一、忠实审（正向：清单 → 成片）

- [ ] 每条 P0 要点：旁白讲到了吗？有画面动作吗？讲得对吗（不只是“出现了”）？
- [ ] 每条 P1 要点：旁白或画面里出现了吗？数字、单位、语境（平均 / 峰值 / 年份）对吗？
- [ ] 图表：按 inventory 的“图表处置”表逐张核对——处置为重画、改编、换画面的图，成片里对应的拍找得到吗？
  重画的读法（坐标轴、排序、标线）和原图一致吗？改编改了读法的，处置表里写明了吗？对照的是原图图片，不是图注。
- [ ] 归属：例子、算例、引言放在原书对应的小节了吗？引言完整吗？
- [ ] 没有原文之外的论断；示意、引申都标注了；示意部分本身数学正确。
- [ ] 深度延伸：逐条核对 inventory 里写的依据（打开那份文档或源码看），画面上标了“延伸 · 原文之外”；延伸只讲“怎么工作”，没有夹带原文没有的论断。
- [ ] 每条 P0 机制都用一组具体数据完整走了一遍（design.md 的机制走查），不是只念了一句定义；`check_design.py` 没有 FAIL。
- [ ] P2 不要求覆盖，但如果出现了，必须准确。

### 二、反查原文（反向：原文 → 成片）

正向审只能查出“清单里有、成片里没有”。清单本身漏掉的内容，拿清单去对是永远查不出来的，必须回到原文。

逐段读这个单元覆盖的原文页，**包括图、图注、侧栏、脚注**，每读完一段问一句：这段的意思，成片里有吗？

- [ ] 每一段正文：它的论断、例子、数字、限定条件，在成片里有对应吗？没有的话，清单里有吗？
- [ ] 每一张图（看原图图片，不是图注）：图里的元素、标注、数字，成片里有对应吗？图注说的意思讲到了吗？
  处置表里漏掉的图、标成“不用”但其实和要点有关的图，算遗漏。
- [ ] 侧栏和脚注：里面的定义、词源、补充说明，有没有该讲而没讲的？
- [ ] 段与段之间的转折（“但是”“因此”“然而”）：论证链条在成片里是完整的吗？
- [ ] 查到的遗漏：先补进 inventory，标注“rN 补”并定好 P0/P1/P2，再按级别算作问题（P0/P1 级的遗漏算 P1 问题）。

反向审的结果单独记一节（见报告模板），这样每轮补了多少清单，一眼就能看出来。
如果连续两轮反向审都没有新发现，说明清单已经基本完整了。

### 三、语义审（画面 ↔ 旁白 ↔ 文字）

逐拍做三件事：

1. **静音看画面**：只看这一拍的画面，写下一句“它在说什么”。
2. **只听旁白**：写下一句“它在说什么”。
3. 两句是否一致？屏幕文字和两者是否一致？

再检查：

- [ ] 标签和它标注的东西是同一个概念（反例：画面演的是“写时扇出”，标签却写“读时组装”）。
- [ ] 同一拍里并排出现的数字，和结论方向一致（反例：并排摆出“写 345k/s > 读 300k/s”，结论却说“写比读少”）。
- [ ] 颜色语义全片一致（红 = 坏 / 慢，绿 = 好 / 已同步……）。
- [ ] 箭头方向 = 数据或请求的流向。
- [ ] 一张图只有一种坐标读法。
- [ ] 一个新手看完这一拍，会不会形成错误的直觉？（例如把扩展和容错混为一谈）

### 四、观感审（好不好看、看不看得下去）

- [ ] **开头**：整章第一拍是章标题、旁白念出章名；开篇 45–90 秒，讲清这章讲什么、分几部分，路线图逐部分点亮、最后标出第一站；每个单元第一拍是站牌、位置（第 k 站 / 共 n 站）和路线图一致；末单元回到路线图收束。新手测试的开篇题（“这一章分几部分、各回答什么问题”）答得出来。
- [ ] lint 全部门槛通过：文字卡 ≤ 15%、无溢出、文字卡 ≤ 3 行、并行补间无冲突、可见文字无书页/图号/内部编号、两份时间轴一致、开头有标题（站牌 / 章标题 + 路线图）。
- [ ] 每一拍画面都有变化：`qa.md` 里没有 `idle` error（动画做完后静止 ≥ 6s），`idle` warn（3–6s）要说得出理由；再看 `frames.md` 的定格表核对画面整体定格；没有连续两拍的画面一模一样。
- [ ] 叙事顺序：站牌之后是钩子问题，结尾回扣；没有“收尾卡出现在中间”；没有重复的结论句。
- [ ] 同屏文字 ≤ 3 行；没有审稿备注、页码这类观众用不上的东西。
- [ ] 文字没有被图形压住：Motion Canvas 段看 `qa.md`，结论为通过、error 为 0——每条要么修掉，要么确认是有意的划掉/打叉/遮罩，给那个节点设 `key="qa-ignore-<说明>"` 后重渲；warn（转场叠化中的重叠、轻微骑边）对照联系表扫一眼。Manim 段没有自动检查，逐拍看 `frames/` 里的全分辨率帧：横条、柱条、线、框都不能从文字中间穿过。
- [ ] 节奏：旁白语速自然（中文约每秒 4–5 字），没有画面已经切走、旁白还在讲上一件事的情况；`audio_timeline.py` 的配音检查没有 error（疑似重复/多读），长停顿 warn 逐条听过；`qa.md` 里没有 overrun（动画超过旁白）。
- [ ] 空框测试：讲“里面的数据怎么变”的拍，框里有具体数据，而不是只写着类别名的空框；`qa.md` 的 fast-move（移动过快）逐条看过，机制的主角已经放慢、一次一个。
- [ ] **新手测试**：拿 design.md 的学习目标问题，让一个没读过这一章的人回答，
  或者**另开一个没有上下文的 agent 会话**，只给它旁白文本和联系表（不给原书、inventory、design），把答案原样记进 review.md。
  做视频的人自己代入新手作答不算。机制走查题答不出来记 P1，回到图式和走查例子去改。
  新手测试的发现默认自动修：每一项都在本单元下一轮里修掉，不递延、不挑、不问用户；只有确实修不了的，才在 review 里注明原因。成片交付时不留未关闭的发现。
  收尾门槛：每轮新手测试判定后，若 0 P0 / 0 P1、走查题全对、且核对后属实的新发现 P2 不超过 3 条，该轮即收尾，不开新轮；剩下的 P2 逐条记为已接受 P2，写进本轮 review.md 并在章报告里汇总（已接受即已关闭，不算未关闭的发现）。核对后不成立的发现不计入这 3 条。有 P0/P1、或走查题不全对、或属实的新 P2 超过 3 条，仍按自动修规则开新轮。
  题包和记录模板用 `scripts/newbie_pack.py` 生成（`rounds/<unit>/rN/newbie/prompt.md`、`answers.md`）。
- [ ] 画面手段：lint 的“画面手段”里只用框、线、文字的场景逐个看——讲机制的场景要回到 design.md 的图式，到 `techniques.md` 挑技法。

## 4. 问题分级

- **P0 讲错或误导**：和原文矛盾；画面和旁白意思相反；数学错误；新手会学错。→ 必须修。
- **P1 缺漏或理解受阻**：P0/P1 要点缺失（包括反查原文新发现的）；叙事顺序乱；关键概念只给几秒；静止过长。→ 应修。
- **P2 瑕疵**：字形、间距、轻微贴边、措辞。→ 顺手修，不单独开一轮；新手测试的发现除外，不论级别默认都在下一轮修掉，修不了的在 review 里注明原因；符合收尾门槛的 ≤3 条新 P2 记为已接受 P2，不开新轮。

用户反馈同样按这三级分；用户明确要求改的，至少算 P1。

## 5. 和上一轮对比

从 r2 起，review.md 开头先写对比，再写本轮审查。对比要回答四个问题：

1. **改了什么**：清单补了哪些条目，分镜改了哪些拍（新增 / 删除 / 重写），代码改了哪些场景。
   可以用 `diff rounds/<unit>/r(N-1)/beats.md rounds/<unit>/rN/beats.md` 看分镜的变化。
2. **上一轮的问题**：逐条标“已修 / 未修 / 部分修”，未修的写原因。
3. **新问题**：这一轮新冒出来的问题，特别是改 A 弄坏了 B 的情况。
4. **整体走向**：P0/P1/P2 的数量、lint 指标、新手测试得分，和上一轮并排列出来。

需要看画面差异时，把两轮的 `sheet.png` 并排看；同一个拍号对应的是同一段旁白，最容易对出变化。

## 6. 交给用户验收

自动审查没有 P0/P1 时，把下面这些交给用户：

- 本轮成片路径，以及 `sheet.png`；
- review.md 的结论一节，以及“与上一轮的差异”（第一次交付时，说明这是第几轮、经过了哪些修改）；
- 还剩下的 P2 问题和你拿不准的地方，主动说出来，不要让用户自己去发现。

用户的反馈**原样**记进 review.md 的“用户反馈”一节，再逐条分级、写修法，作为下一轮的输入。
用户确认满意后，写 `rounds/<unit>/FINAL`：

```
定稿轮次：r3
日期：YYYY-MM-DD
用户确认：“<用户的原话>”
```

用户没有明确确认之前，不要宣布定稿。
