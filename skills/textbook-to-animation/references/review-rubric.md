# 三道审查清单与报告模板

每轮审查对象：一个学习单元的成片（或至少每拍的抽帧加 beats.md 加场景源码）。三道审查都要做，顺序随意，但报告合在一起。

## 准备

- `python scripts/lint_scenes.py <场景目录> --manim <manim 目录>`：贴出摘要和未过的门槛。
- 每拍抽一帧（取拍中点，时间来自 timeline.json），拼成联系表：
  `ffmpeg -ss <t> -i unit.mp4 -frames:v 1 frames/<拍号>.png`，再用
  `ffmpeg -pattern_type glob -i 'frames/*.png' -vf "scale=426:-1,tile=6x5" -frames:v 1 sheet.png`
  （或者逐张看）。深色背景下 blackdetect 会误报，不能用它判断黑帧。
- 打开 inventory.md 和 design.md。

## 一、忠实审（对原文）

- [ ] 每条 P0 要点：旁白讲到了吗？有画面动作吗？讲得对吗（不只是“出现了”）？
- [ ] 每条 P1 要点：旁白或画面里出现了吗？数字、单位、语境（平均 / 峰值 / 年份）对吗？
- [ ] 图表：重画的书中图表，读法（坐标轴、排序、标线）和原图一致吗？改了读法的话，说明了吗？
- [ ] 归属：例子、算例、引言放在原书对应的小节了吗？引言完整吗？
- [ ] 没有原文之外的论断；示意、引申都标注了；示意部分本身数学正确。
- [ ] P2 不要求覆盖，但如果出现了，必须准确。

## 二、语义审（画面 ↔ 旁白 ↔ 文字）

逐拍做三件事：

1. **静音看画面**：只看这一拍的画面，写下一句“它在说什么”。
2. **只听旁白**：写下一句“它在说什么”。
3. 两句是否一致？屏幕文字和两者是否一致？

再检查：

- [ ] 标签和它标注的东西是同一个概念（反例：画面演的是“写时扇出”，标签却写“读时组装”）。
- [ ] 同一拍里并排出现的数字，和结论方向一致（反例：并排摆出“写 345k/s > 读 300k/s”，结论却说“写比读少”）。
- [ ] 颜色语义全片一致（红 = 坏 / 慢，绿 = 好 / 已同步……）。
- [ ] 箭头方向 = 数据或请求的流向。
- [ ] 一张图只有一种坐标读法。
- [ ] 一个新手看完这一拍，会不会形成错误的直觉？（例如把扩展和容错混为一谈）

## 三、观感审（好不好看、看不看得下去）

- [ ] lint 门槛：文字卡 ≤ 15%，静止 ≤ 40%，单次静止 ≤ 6s，无溢出。
- [ ] 每一拍画面都有变化；没有连续两拍的画面一模一样。
- [ ] 叙事顺序：开头是钩子问题，结尾回扣；没有“收尾卡出现在中间”；没有重复的结论句。
- [ ] 同屏文字 ≤ 3 行；没有审稿备注、页码这类观众用不上的东西。
- [ ] 节奏：旁白语速自然（中文约每秒 4–5 字），没有画面已经切走、旁白还在讲上一件事的情况。
- [ ] **新手测试**：拿 design.md 的学习目标问题，让一个没读过这一章的人回答
  （或者另开一个没有上下文的 agent 会话，只给它旁白文本和联系表，不给原书），记录答错的题和原因。

## 问题分级

- **P0 讲错或误导**：和原文矛盾；画面和旁白意思相反；数学错误；新手会学错。→ 必须修，修完重审。
- **P1 缺漏或理解受阻**：P0/P1 要点缺失；叙事顺序乱；关键概念只给几秒；静止过长。→ 应修。
- **P2 瑕疵**：字形、间距、轻微贴边、措辞。→ 顺手修。
