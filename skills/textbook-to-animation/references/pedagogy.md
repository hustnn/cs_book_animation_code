## 1. 几条底层原则

这些原则来自多媒体学习研究（Mayer），在这里按“教材 → 动画”的场景改写：

- **通道原则：** 讲机制时，用“旁白 + 画面”，不用“屏幕文字 + 画面”。眼睛只有一双，读字就没法看图。
- **冗余原则：** 不要把旁白逐字打在屏幕上。字幕可以作为辅助（SRT），但不要做成画面主体。
- **连贯原则：** 和学习目标无关的装饰、音效、花絮，删掉。
- **信号原则：** 用高亮、颜色、箭头告诉观众“现在看这里”。一拍只高亮一处。
- **分段原则：** 一拍一个想法，一个单元一个问题。
- **具体先于抽象：** 先给具体例子（Twitter 时间线），再给术语（扇出），最后给一般规律（负载参数决定架构）。
- **走一遍胜过讲一遍：** 机制用一组具体数据从头走到尾（worked example），观众跟着一条数据看它每一步去了哪里、变成了什么。
  抽象的“小段并进大段”要等观众看过一次真实数据的合并之后再出现。画面怎么做见 `visual-schemas.md`。

## 2. 单元的叙事弧

```
钩子（问题或反直觉现象）
 → 直觉（最简单的例子，先让人“看到”）
 → 机制（拆开看为什么，一层一层加复杂度）
 → 证据（书里的数字、案例、图）
 → 边界（什么时候不成立，代价是什么，书里的限定条件）
 → 回扣（回答钩子问题，一句话结论）
 → （可选）停下来想一想：一个小问题，下一个单元开头揭晓
```

书的论证顺序通常已经接近这个结构，**默认跟书走**。确实需要调整时（比如把书末的结论提到开头当钩子），在 design.md 写明理由。

整章层面用总—分—总：开头加一段 30–60 秒的总述，先总说本章讲什么——核心思想加各单元的路线，再进入分述；末单元收束全章。

## 3. 通俗化手法

| 手法 | 例子 | 注意 |
|---|---|---|
| 数量级翻译 | MTTF 10–50 年 → 1 万块盘的集群每天坏一块 | 换算必须来自原文，或者是能验证的算术 |
| 对比成对出现 | 同样 100 MB/s：10 万个 1KB vs 每分钟 3 个 2GB | 两边只变一个维度 |
| 主线例子 | 用 Twitter 时间线串起负载 → 性能 → 扩展 | 例子要贯穿多个单元，不要只出现一次 |
| 让数字有感觉 | 345k 写/秒 → 每秒把一本书的字写 N 遍 | 类比不能改变原数字的含义 |
| 先错后对 | 先演“看平均值”得出错误结论，再演“看 p99” | 错误示范要清楚标明是错的（颜色、✗） |
| 拟人化或角色 | 请求是排队的人，服务器是窗口 | 隐喻要能一直撑到机制讲完，不要中途换比喻 |
| 停下来想一想 | “做法 2 下，名人发一条推会怎样？” | 下一拍揭晓答案 |

## 4. 深度演示模式库

书里常常一句话带过、但动画能让人“看见”的模式。每个单元至少用一个。

| 模式 | 动画做法 | 适用的概念（举例） | 工具 |
|---|---|---|---|
| **概率放大** | N 个独立事件逐个点亮，同时画出 1−(1−p)ᴺ 曲线 | 尾延迟放大、多请求遇到慢请求、大集群里至少一台坏 | MC 点亮 + Manim 曲线 |
| **分布排序** | 按到达顺序的柱子 → 动画排序 → 标出百分位高度 | 百分位、中位数和均值、长尾 | Manim |
| **聚合陷阱** | 两组数据分别求统计量再平均 vs 合并后求 | 平均百分位、平均的平均 | Manim |
| **排队** | 单通道队列，一个慢请求挡住后面所有请求；分别显示服务端计时和客户端计时 | 队头阻塞、利用率与延迟、背压 | MC |
| **闭环 vs 开环** | 两个压测客户端并排：一个等上一个回来才发，一个按固定节奏发 | coordinated omission、限流 | MC |
| **相关 vs 独立** | 独立：节点随机零星变红；相关：所有节点在同一时刻一起变红 | 硬件故障 vs 软件 bug、共因故障 | MC + Manim |
| **扇出 / 扇入** | 一个点向 N 个点发箭头，N 由真实数字缩放 | 时间线扇出、scatter-gather、广播 | MC |
| **两条路径对比** | 同一请求走两种架构，并排比较各步的代价 | 读时组装 vs 写时扇出，同步 vs 异步复制 | MC |
| **时间线错位** | 两个节点的本地时间轴并排，事件在其中一个上延迟到达 | 复制延迟、时钟偏差、因果顺序 | MC |
| **展开 / 折叠** | 一个抽象（一行 SQL）展开成底下的复杂度，再折叠回去 | 抽象与偶然复杂度、分层 | MC |
| **扩缩阶梯** | 负载曲线 vs 容量线（自动扩缩紧贴，手动扩缩是阶梯加余量） | 弹性、容量规划 | Manim |
| **状态机走一遍** | 状态节点亮起，事件触发迁移，非法迁移标红 | 事务隔离、共识协议、TCP | MC |
| **反例构造** | 一步步构造出一个违反直觉的执行序列 | 写偏斜、幻读、脑裂、线性一致性违例 | MC |
| **不变量守恒** | 操作前后有一个量始终显示且保持不变（或被破坏） | 一致性、quorum 交集 w+r>n | Manim / MC |
| **一条数据的一生** | 跟着一个有身份的数据块走完整条路径：写日志 → 进内存 → 刷盘 → 合并 → 下沉 | 存储引擎、复制管道、消息队列 | MC（`KV` + 全景图） |
| **有序插入、其余让位** | 新块落下前，比它大的先让一格 | 有序表、B 树页内、跳表 | MC（`Slots.insertSorted`） |
| **代价计数** | 角落的计数器随每次读盘 / 写盘 / 网络往返加一，两种方案各数一遍 | 读放大、写放大、往返次数 | MC（`Counter`） |
| **钻进去看** | 推镜头到一个部件，或全景退后、部件放大到前景讲内部，再回到全景 | 索引页、过滤器、缓存行 | MC（`Cam`、剖面放大） |
| **共享坐标轴** | 几层画在同一根轴上（键、时间、地址），位置和宽度就是范围 | 分层合并、分区、时间窗口 | MC |

## 5. 常见误区清单（CS / 系统类教材）

设计每个单元时，问一句：“观众带着什么错误直觉进来？”常见的有：

- 平均值代表大多数人的体验
- 加机器就能线性扩展
- 冗余等于不会失败
- 延迟和响应时间是一回事
- 吞吐高就是快
- 分布式系统里“同时”是有意义的
- 写进去就能马上读到
- 事务能自动解决所有并发问题

一个误区拆一次就够，用“先错后对”的手法。

## 6. 语言风格

- 口语、短句，一句话不超过 25 个字。
- 术语第一次出现时：中文（English），之后只用中文或只用约定的那个。
- 先结论后理由：“做法 2 更划算，因为读比写多两个数量级。”
- 少用“非常”“极其”，多用具体数字。
- 不逐字翻译原文。用自己的话转述，引言除外（引言要短，并注明出处）。
