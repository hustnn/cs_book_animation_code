# 空白模板

## figures.md（全书图表对照表，第 0 步做一次）

```markdown
# <书名> 图表对照表

> 来源：<书名/版本> PDF（共 N 页，`pdfinfo` 核对）；书页 = PDF 页 − K（实测）。
> 提取：`pdftotext -layout` 抽全文，按本书图注格式找图注，逐条到页面图片上确认是图注而不是正文引用；
> `pdfimages -list` 只作粗核（矢量图数不到，封面、图标会被多数）。
> 归属：按正文**第一次讨论**这张图的小节定，不按图注所在页定（图常浮排到后面几页）。

## 总数核对
| 项目 | 数值 |
|---|---|
| 带编号的图 | n 张（图 1-1 至 图 m-k），按章：第 1 章 a 张；第 2 章 b 张；… |
| 带编号的表 | t 张 |
| 有原书图的小节 / 全部小节 | x / y：其余小节没有原图，分镜需要原创画面 |

## 容易误读的地方
- 图注页 ≠ 讨论页的图：…
- 正文里以“图 N-M.”开头、看着像图注的引用句：…

## 对照表
| 图号 | 图注（原文照录） | PDF 页 / 书页 | 第一次讨论它的小节 |
|---|---|---|---|
| 图 1-1 | … | p? / 书 p? | §1.1 … |
```

## inventory.md

```markdown
# <章节名> 要点清单

> 原文：<书名/版本>，书页 pA–pB（PDF pX–pY；书页 = PDF 页 − K，实测）。
> 抽取：`pdftotext -layout -f X -l Y book.pdf /tmp/<chapter>-fulltext.txt`（全文不入库）。
> 图表：本章 n 张（见 figures.md）；原图页面图片：`pdftoppm -png -r 150 -f P -l P book.pdf /tmp/<chapter>-figs/<图号>`（不入库），逐张看过图本身。

## §N.1 <小节名>（书页 p?–p?）

| ID | 要点（自己的话） | 类型 | 级别 | 书页 | 图/表 | 可视化潜力 | 补充轮次 |
|---|---|---|---|---|---|---|---|
| N.1-1 | … | 定义 | P0 | p? | — | 高：… | |
| N.1-9 | … | 例子 | P1 | p? | 图 N-3 | 中：… | r2 补 |

## 图表处置（本章每张图一行）
| 图号 | 讨论它的小节 | 图里说了什么（自己的话：坐标、排序、标线、关键数字） | 相关要点 ID | 处置 | 单元 · 拍号 | 改了什么 / 理由 |
|---|---|---|---|---|---|---|
| 图 N-1 | §N.1 | 横轴…、纵轴…；… | N.1-3 | 重画 | U2 · b5–b7 | — |
| 图 N-2 | §N.3 | … | N.3-1 | 改编 | U4 · b12 | 静态对比改成逐步生长，读法不变 |
| 图 N-3 | §N.4 | … | — | 不用 | — | 装饰性示意，与本章要点无关 |

处置只有四种：重画（按原图读法）/ 改编（拆步演出或换表现方式，写明改了什么）/ 换画面（写明理由）/ 不用（写明理由）。
和 P0 要点相关的图不能“不用”。

## 原文没有、但计划加入的内容
| 内容 | 性质（示意 / 类比 / 引申 / 深度延伸） | 理由 | 依据（深度延伸必填：文档、源码文件、论文） | 画面上的标注方式 |

## 统计
P0 a 条 / P1 b 条 / P2 c 条；其中各轮补充：r2 补 x 条，r3 补 y 条
```

“补充轮次”留空表示初版就有；写分镜、实现或反查原文时发现的遗漏，补进来并标“rN 补”。
每轮补了多少条，能直接看出清单在收敛（理想情况是越来越少，直到连续两轮为 0）。

## rounds/<unit>/rN/（每轮快照）

```
rounds/<unit>/
├── r1/
│   ├── beats.md        # 本轮所用分镜的副本
│   ├── timeline.json   # 本轮所用时间轴的副本
│   ├── <unit>.mp4      # 本轮成片
│   ├── sheet.png       # 每拍抽一帧的联系表
│   ├── lint.txt        # lint_scenes.py 的输出
│   └── review.md       # 本轮审查报告（模板见 review-rubric.md 第 7 节）
├── r2/
└── FINAL               # 定稿轮次、日期、用户确认的原话
```

快照存好后不再修改；要改就进入下一轮。比较两轮：`diff r1/beats.md r2/beats.md` 看分镜变化，并排看两张 `sheet.png` 看画面变化。

## beats.md

```markdown
# 单元 U1：<名字> 分镜

| 拍 | 旁白 | 画面动作 | 屏幕文字 | 要点 | 工具 |
|---|---|---|---|---|---|
| b1 | 你打开 App，转了 3 秒才出来——服务器说它只用了 50 毫秒。谁在撒谎？ | 手机转圈 3s；服务器面板显示“50 ms” | 3 s vs 50 ms | 1.9-18 | MC |
| b2 | 响应时间包括真正处理的时间、网络延迟和排队延迟。 | 拍首出一条空框（终态总宽 600，上方标“客户端看到的全部时间”）；三段按旁白填进去：念到“处理”长处理段，念到“网络延迟”长网络段，念到“排队延迟”长排队段（三段 300/120/180）；每段的名字标在该段正下方、和该段一起出现 | 处理 / 网络 / 排队 | 1.9-3 | MC |
| b3 | … | … | … | … | … |
```

开头两种固定的拍（样本：`examples/opening/beats.md`、`examples/lsm/beats.md` 的 w0）：

```markdown
| o1 | 第三章，存储与检索。 | 标题拍（演示 +1.2s）：“第 3 章”淡入，章名浮现，下划线展开，原书章名淡入 | 第 3 章 / 存储与检索 | 开篇 | MC |
| w0 | 第三站：排好序的段。 | 站牌（演示 +0.8s）：“存储与检索 · 第 3 站 / 共 15 站”、单元标题、迷你路线条（当前站黄色带圈）；下一拍开头收成页眉 | <单元标题> | 站牌 | MC |
```

规则：旁白 1–2 句；画面动作以动词开头；屏幕文字 ≤ 15 字；每拍至少关联一条要点，或明确标注为“过渡”。
机制一步一拍，主角一次动一个；变换要几秒、旁白一句就说完的，在拍号后标“演示 +N s”，beats.json 里写 `"hold": N`。

画面动作还要写清三件事（实现时据此用 `at()`、`attach()` 落地，见 motion-canvas.md“摆位”一节）：
- **跟旁白的哪个词走**：一拍里有几个动作时，写“念到 X 时 …”；只有一个信息点的长旁白，写一段铺满整拍的慢动作。
- **终态**：会长大、移动的元素写出最终的大小和位置，好给它留生长通道。
- **标签说明的是哪个对象**：写“标在 X 的右侧 / 正下方 / 卡片内底部”，而不是只写标签文字。

## beats.json（喂给 TTS）

```json
[
  {"id": "b1", "text": "你打开 App，转了 3 秒才出来——服务器说它只用了 50 毫秒。谁在撒谎？"},
  {"id": "b2", "text": "…"},
  {"id": "b3", "text": "四个段并成一个，同一个键只留最新的。", "hold": 2.5}
]
```

`hold`（可选，0–10 秒）：演示拍，旁白念完后再留这么久的静音给画面。`audio_timeline.py` 把它计入 `dur`，拼接时插入同样长的静音。

## timeline.json（audio_timeline.py 的输出）

```json
{
  "unit": "latency",
  "total": 312.4,
  "pad": 0.35,
  "beats": [
    {"id": "b1", "start": 0.0, "dur": 5.36, "speech": 5.01, "file": "b1.wav", "text": "…"},
    {"id": "b2", "start": 5.36, "dur": 4.12, "speech": 3.77, "file": "b2.wav", "text": "…"}
  ]
}
```

`dur` 已含每拍末尾的留白（`--pad`，默认 0.35s）。
