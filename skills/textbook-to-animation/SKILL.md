# 教材 → 动画讲解视频

目标：**通俗易懂，同时不丢深度和完整性。** 这三者之间的张力，靠三种载体分工来解决：

| 载体 | 负责什么 | 不该负责什么 |
|---|---|---|
| **画面（动画）** | 机制、结构、因果、数量级、“为什么”——观众看得见的东西 | 长句、定义全文、清单 |
| **旁白（TTS 配音）** | 论证、定义、例子、证据、限定条件——要点覆盖的主要载体 | 只有画面才能讲清的过程 |
| **屏幕文字** | 锚点：术语、关键数字、一句结论（同屏 ≤ 3 行） | 代替旁白 |

为什么这样分：如果把“每条要点都要以画面文字出现”当作验收标准，视频就会退化成会动的 PPT——
大半时长是文字卡，动画播完就静止，观众一边读字一边看图，两样都顾不上；
而且只核对文字的审查，会漏掉“画面和文字意思相反”这类错误。
这些失败模式和对应规则的来由，见 `references/failure-modes.md`。

## 贯穿全程的两条原则

1. **原文是唯一的权威，其余都是 outline。** inventory、design、beats 都是对原文的有损压缩。
   只照着它们生成，它们漏掉的东西动画里就不会有；审查时再拿同一份清单去对，也查不出来。
   所以写分镜、写场景代码、做审查时，都要回到对应的原文页（含图、图注、侧栏、脚注）。
   发现原文里有、清单里没有的内容，先补进清单（标注“rN 补”），再往下改。
2. **多轮迭代，每轮完整保留。** “生成 → 审查 → 修改”按轮次循环，每轮的产物存进 `rounds/<unit>/rN/`，
   存好后不再改动，修改一律进入下一轮，这样任意两轮都能直接对比。
   自动审查清零后交给用户看，用户确认满意才算定稿。

## 每章的产物

```
<chapter>/
├── inventory.md      # 1. 分级要点清单（原文 → 要点，带页码、类型、优先级）+ 图表处置表；每轮可补充，后补的条目标注“rN 补”
├── design.md         # 2. 教学设计（学习单元、钩子、误区、核心画面、深度演示、要点 → 载体映射）
├── beats.md          # 3. 分镜：旁白先行，一拍一行（当前工作版本）
├── beats.json        # 3'. 从 beats.md 抽出的旁白文本（喂给 TTS）
├── audio/<unit>/     # 5. 每拍一个音频文件
├── timeline/<unit>.json  # 5'. audio_timeline.py 生成：每拍时长，场景代码据此定时
├── subs/<unit>.srt   # 5'. 同一份时间轴生成的字幕
└── rounds/<unit>/    # 7. 每轮一个快照目录，存好后只读
    ├── r1/
    │   ├── beats.md        # 本轮所用分镜的副本
    │   ├── timeline.json   # 本轮所用时间轴的副本
    │   ├── <unit>.mp4      # 本轮成片
    │   ├── sheet.png       # 每拍抽一帧的联系表
    │   ├── lint.txt        # lint_scenes.py 的输出
    │   └── review.md       # 本轮审查、与上一轮的对比、用户反馈
    ├── r2/ …
    └── FINAL           # 定稿时写入：定稿轮次（如 r3）、日期、用户确认的原话
场景代码：motion-canvas/src/scenes/<chapter>/*.tsx、manim/<chapter>/*.py
```

场景代码用版本库管理，每轮在 review.md 里记下当时的 commit；没有版本库时，把本轮改过的场景文件也复制进快照目录。

原文全文只放本地临时目录（如 `/tmp/<chapter>-fulltext.txt`），不进版本库（版权），但在 inventory.md 头部写清楚
怎么重新抽取（`pdftotext -layout -f A -l B book.pdf`，以及书页和 PDF 页的换算）。
原图的页面图片同样只放本地（如 `/tmp/<chapter>-figs/`），不进版本库；进版本库的只有图号、图注、页码这类索引（`figures.md`）。

## 第一次在项目里使用：搭建

本 skill 自带全部模板和辅助代码，在 `assets/` 下。新项目按下表复制（已有项目缺哪个补哪个）：

| skill 里的文件 | 复制到 | 作用 |
|---|---|---|
| `assets/motion-canvas/theme.ts` | `motion-canvas/src/lib/theme.ts` | 配色、颜色语义、字体、字号、安全区 |
| `assets/motion-canvas/beats.ts` | `motion-canvas/src/lib/beats.ts` | `beat()`：动画时长由旁白音频决定 |
| `assets/motion-canvas/layout.ts` | `motion-canvas/src/lib/layout.ts` | 防压字的摆位写法：`attach`（标签跟着对象的边走）、`row`/`column`（按尺寸排开）、`edgePointIn`（停在节点旁） |
| `assets/motion-canvas/qa.ts` | `motion-canvas/src/lib/qa.ts` | 渲染 QA：`--qa` 时逐拍检查文字被压、被线穿过、骑边、互叠、出画，标签先于对象出现（orphan），动画超时（overrun）与做完后静止过久（idle） |
| `assets/motion-canvas/card.tsx` | `motion-canvas/src/lib/card.tsx` | 文字卡（≤ 3 行，旁白驱动），只用于引言和小结 |
| `assets/motion-canvas/render/headless.ts` | `motion-canvas/src/headless.ts` | 无头渲染入口 |
| `assets/motion-canvas/render/headless.html` | `motion-canvas/public/headless.html` | 加载上面的入口 |
| `assets/motion-canvas/render/render.mjs` | `motion-canvas/scripts/render.mjs` | 渲染驱动（在 `motion-canvas/` 下运行） |
| `assets/motion-canvas/render/render-lock.mjs` | `motion-canvas/scripts/render-lock.mjs` | 渲染锁：`render.mjs` 自动用，整台机器同一时间只跑一个渲染 |
| `assets/motion-canvas/render/vite.config.ts` | `motion-canvas/vite.config.ts` | Vite 插件配置，文件头写了依赖清单 |
| `assets/manim/theme.py`、`assets/manim/beats.py` | `manim/` | Manim 版的 theme 和 `Beats` |

## 流程

按顺序走，每一步过了门槛再进下一步。整章不要一口气做完：**先做一个学习单元的样片，跑完全部审查，定型后再铺开。**
第 1、2 步每章做一次；第 3–7 步对每个学习单元按轮次循环（r1 → 审查 → r2 → …），直到定稿。

### 0. 全书一次性准备

视觉规范（配色、颜色语义、字体、分辨率、安全边距）定在 theme 里；搭好上面的渲染管线；
选定 TTS 引擎和音色；把反复出现的视觉元素做成组件。工程细节见 `references/motion-canvas.md`、`references/manim.md`。

**全书图表对照表（`figures.md`）**：每张带编号的图和表一行——图号、图注原文、PDF 页 / 书页、**正文第一次讨论它的小节**。
做法：`pdftotext -layout` 抽出全文后按这本书的图注格式找（如 `grep -nE '^\s*(Figure|Fig\.|Table|图|表)\s*[0-9]+[-.][0-9]+'`），
逐条到页面图片上确认是图注、不是正文里的引用句。两个常见的坑：
- 图会浮排到后面几页，图注所在页常常已经是下一小节的页码范围：归属按“正文第一次提到它”的小节定，不按图注页定。
- `pdfimages -list` 只数位图，矢量画的图数不到，封面、图标又会被多数：只能拿来粗核，图的总数以图注为准。
模板见 `references/templates.md`。之后每章的第 1 步从这张表取本章的图。

### 1. 通读 → 分级要点清单（inventory.md）

逐节读原文全文，包括图注、侧栏、脚注，**不要只看标题**。每条要点一行：

`ID | 要点（自己的话转述）| 类型 | 优先级 | 书页 | 图/表 | 可视化潜力`

- **类型：** 定义 / 论断 / 机制 / 数字 / 例子 / 图 / 限定条件 / 交叉引用 / 花絮
- **优先级（决定载体，也决定审查力度）：**
  - **P0** 核心概念、定义、主论断：必须讲透，**必须有画面动作**
  - **P1** 支撑证据、关键数字、主例子：必须准确，旁白讲到即可
  - **P2** 出处、花絮、长清单的细项：可选，可只在旁白里一句带过，或放进视频简介
- **数字** 原样记下单位和语境（“平均”“峰值”“某年数据”）：语境丢了，数字就会被误读。
- 另起一节记**“原文没有、但我们想加的”**（示意模型、类比、引申），每条注明理由；成片里出现时必须标注“示意”或“引申”。

**看图本身，不只读图注。** `pdftotext` 只抽得出图注，图里的坐标轴、排序、标线、箭头、数字、标注都在图上。
把本章每张图所在的页渲染成图片（`pdftoppm -png -r 150 -f P -l P book.pdf /tmp/<chapter>-figs/<图号>`），用看图的能力逐张读，
读到的内容按要点记进清单（类型“图”，在“图/表”列写图号）。

**每张图定一个处置**，记进 inventory 的“图表处置”表：
- **重画**：按原图的读法（坐标、排序、标线、比例）重画；
- **改编**：拆成几步用动画演出来，或者改变表现方式（例如静态的对比图改成逐步生长）——改了读法的，写明改了什么、为什么；
- **换画面**：用别的画面讲同一件事，写明理由；
- **不用**：写明理由（例如纯装饰、与本章要点无关）。和 P0 要点相关的图不能“不用”。

处置表同时写上每张图落在哪个单元、哪几拍，审查时按它核对。

**门槛：** 每个小节都读过全文；本章每张图都看过图本身、都有处置；P0 条目一般占 20–30%；所有数字都核对过原文。

### 2. 教学设计（design.md）

**按概念切学习单元，不按目录标题切段。** 一个单元 3–6 分钟，讲透一个问题，可以跨几个小节，也可以只是一个小节的一半。
每个单元写清楚：

1. **钩子问题**：观众为什么要关心？用一个具体场景提问（如“写进去的数据，多久才能被读到？”）。
2. **学习目标**：看完能回答的 2–3 个问题（之后也用作“新手测试”的题目）。
3. **常见误区**：要主动拆掉的错误直觉（如“均值能代表用户体验”）。
4. **核心画面**：贯穿整个单元的一个视觉隐喻或主线例子，尽量延续到下一个单元。
5. **深度演示**：书里一句话带过、但动画能让人“看见”的点（概率放大、分布排序、排队、相关故障……），
   每单元至少一个。模式库见 `references/pedagogy.md`。
6. **要点 → 载体映射**：每条 P0/P1 要点落到哪一拍、由画面还是旁白承载。
7. **叙事顺序**：默认跟原书的论证顺序；要调整就写明理由。**新增内容要编织进叙事，不要追加成补丁段。**
8. **总—分—总**：整章开头加一段 30–60 秒的总述，先总说本章讲什么——核心思想加各单元的路线，再进入分述；末单元收束全章。不要一上来就讲第一个单元，观众不知道这章要去哪。

**门槛：** 每条 P0 都有画面动作，每条 P1 都有承载的拍；单元之间没有重复的结论句。

### 3. 分镜（beats.md）——旁白先行

**动笔前先重读原文。** 打开这个单元覆盖的原文页（含图、图注、侧栏、脚注）和第 1 步渲染出的原图图片，和 inventory、design 对照着写。
重画或改编原图的拍，在画面动作里注明对应哪张图、按什么读法画（只写在分镜里，不上画面）。
inventory 和 design 只是 outline，内容以原文为准：例子的细节、数字的语境、图的读法、论证的先后，都从原文取。
原文里有、清单里没有的要点，先补进 inventory（标注“rN 补”）并定好优先级，再写进分镜。

先写旁白，再为每一拍设计画面。一拍一行：

`拍号 | 旁白（1–2 句，口语）| 画面动作（动词开头：出现/移动/变色/排序/放大…）| 屏幕文字（≤ 15 字）| 要点 ID | 工具`

- 每拍 3–8 秒，**每一拍画面都要有变化**；超过 6 秒没有变化，就是该加动作或该拆拍的信号。
  一拍里有几个信息点时，画面动作按旁白里的词分步写（“念到 X 时 A 出现，念到 Y 时 B 出现”），实现时用 `at()` 对齐。
- **画面动作写清终态**：会长大、移动的元素写出最终的大小和位置；每个标签写明它说明的是哪个对象。
  实现时据此留出生长通道、把标签挂到对象上——文字被压、骑边、读错对象，大多是终态没想清楚。
- 旁白像讲给同事听：短句，先结论后细节，术语第一次出现时给中英对照。
- 数字放在画面里，并让它“有感觉”：换算成日常尺度，或和另一个数字对比。
- 结尾一拍回扣钩子问题；需要时加一拍“停下来想一想”。
- 写完之后，**只读旁白**检查一遍：要点全吗、逻辑顺吗；**只读画面列**再检查一遍：能看出机制吗。

空白模板见 `references/templates.md`；一个从要点清单到两个单元完整分镜的示例见 `references/example-unit.md`。

### 4. 工具路由

| 内容 | 工具 |
|---|---|
| 节点、消息、请求流、拓扑、状态变化、时序、表格和数据结构变换 | **Motion Canvas** |
| 坐标系、函数曲线、概率和分布、公式推导、几何和集合论证 | **Manim** |
| 机制 + 定量结论（如“扇出 N 个后端” → “1−0.99ᴺ 曲线”） | MC 演机制，切到 Manim 出曲线，**两段共用同一组配色和数字** |
| 纯文字 | 尽量不用。引言、小结可以用 `card.tsx`，每单元最多 1 张，并配旁白 |

细节见 `references/tool-routing.md`。

### 5. 配音与时间轴

1. 把 beats.md 的旁白抽成 `beats.json`（`[{id, text}]`），用 TTS 生成每拍一个音频，放进 `audio/<unit>/<拍号>.wav`。
   TTS 引擎随环境选（云端 TTS、本地开源模型都可以），要求只有两条：全书同一个音色；输出同采样率的 PCM wav。
   第一次用某个引擎前，先合成一两拍试听：多音字、英文术语、数字（“p99”“1.2 秒”）的读法要单独检查。
   录完不用手算：下一步的 `audio_timeline.py` 会自动逐拍检查配音——**疑似重复/多读**（有声段语速比单元中位数慢 30% 以上，TTS 在固定位置截断、把后半句重复几遍就是这个特征）记 error、退出码非零；长停顿、语速过快、首尾静音过长记 warn。疑似重复的拍拆成两拍或改写法重录，**不要原句重试**（原因见 `references/motion-canvas.md` 坑表）。脚本只是筛查：英文术语、数字的读法仍要人耳试听。
2. 运行
   `python <skill>/scripts/audio_timeline.py audio/<unit> --beats beats.json -o timeline/<unit>.json -o motion-canvas/src/timeline/<unit>.json --srt subs/<unit>.srt --concat-list audio/<unit>.txt`，
   得到每拍时长、字幕、音频拼接清单和配音检查结果。`-o` 给两次：章节目录和 Motion Canvas 工程里的两份时间轴一次写出，
   不会出现“重算了一份、渲染还在用旧的那份”。同一拍号既有 `.wav` 又有 `.mp3` 时脚本只用 `.wav` 并警告。
3. 场景代码用 `beat(id, 动画)`：先跑动画，再补等到该拍音频的时长（MC 用 `lib/beats.ts`，Manim 用 `beats.py`）。
   **不要手写 `waitFor(23.1)` 这样的魔法数字。** 还没有音频时，`beat()` 会按旁白字数估算时长，可以先把节奏搭起来。
4. 视频静音渲染，拼接时用 ffmpeg 把音频混进去（命令见 `references/motion-canvas.md` 的“拼接与混音”一节）。

### 6. 实现与渲染

- 先读 `references/motion-canvas.md` 或 `references/manim.md` 里的“坑”一节，以及 `references/qa-rules.md` 第 2 节（十类常见缺陷与预防写法）。
- **用预防写法写场景，而不是按绝对坐标手摆**：标签用 `attach(label, 对象, side)` 挂到它说明的对象边上（对象长大、移动时跟着走），容器里的文字用 `attach(…, padding, true)` 放内侧，一排元素用 `row()` / `column()` 排开，运动停靠点用 `edgePointIn()` 停在节点旁边，一拍里的多个动作用 `at('词', 动作)` 跟着旁白展开，先后发生的动作用 `chain(…)`。有意的划掉、打叉给节点设 `key="qa-ignore-<说明>"`。
- **写每个场景前，再对照一遍这些拍对应的原文段落和原图图片。** 标签、数字、图表的坐标和读法以原文为准，
  不凭分镜里的转述；分镜和原文对不上时，以原文为准，并回头改分镜。
- 颜色、字体从 theme 引用；文字一律设 `maxWidth` + `textWrap`（Manim 用 `theme.py` 的 `txt()`，会自动缩到安全区内）。
- **自检循环**（详见 `references/qa-rules.md` 第 4、5 节）：tsc → lint → `qa_chapter.py`（整章渲染 QA 并汇总）→ `sample_frames.py`，每条 error 要么修掉、要么确认是有意效果并设 `qa-ignore`，修完重跑；**自检全部通过才进入第 7 步的人工审查**。不要用调大阈值的办法让报告变干净。
- 渲染前：MC 跑 `npx tsc --noEmit`，再跑
  `python <skill>/scripts/lint_scenes.py <场景目录> --manim <manim 目录> --timeline-dir <chapter>/timeline --narration <chapter>`。
  除了文字卡、静止、超宽这些门槛，它还会拦下三类渲染后很难看出来的问题：**并行补间冲突**（同一属性在一组
  `all(…)` / `sequence(0, …)` 里被补间两次，“先去再回”“先红后绿”这类动作根本播不出来，定格帧却看着正常）、
  画面和旁白里的**书页、图号、“书里/原图”、内部编号**、**两份时间轴不一致**。
- 渲染：MC 用 `python <skill>/scripts/qa_chapter.py --project motion-canvas --dir src/scenes/<chapter>`，一条命令把这一章的场景逐个用 `--qa` 渲染并汇总；
  默认只重渲改过的场景（场景文件或它 import 的 lib、组件、时间轴内容变了才重渲），修完再跑一遍很快。
  单个场景也可以在 `motion-canvas/` 下 `node scripts/render.mjs <场景名> --qa`。
  Manim 用 `python <skill>/scripts/render_lock.py run <单元> -- manim -qm <文件> <场景类>`。
  **渲染锁**：整台机器同一时间只跑一个渲染（几个代理并行做不同单元时排队，不抢内存、不抢 Chrome）。
  `render.mjs` 自己拿锁、渲完放锁（`qa_chapter.py` 逐个场景各拿一次，别的单元能插进来）；Manim 和其他重活用 `render_lock.py run` 包一层。
  等锁超过 `--lock-timeout`（默认 90 分钟）就退出码 3、不渲染：停下来汇报，不要绕过锁。持锁进程崩了，下一个等锁的会自动清掉。
  `--qa` 的画面和时长与正常渲染完全一致，同时在每拍 5 个时刻（拍首、25%、50%、75%、拍末）检查文字被图形压住、
  被线穿过、骑在图形边上、文字互叠、出画、标签先于对象出现，以及动画超过旁白、做完后静止过久，
  每个场景的报告写到 `output/<场景名>.qa.json`；汇总写到 `output/qa-summary.md`：门槛结论、每个场景一行、
  要修的 error 清单、静止 3–6s 的拍、没被 QA 覆盖的场景。
  每条 error 要么修掉，要么确认是有意的（划掉、打叉、遮罩）并给那个节点设 `key="qa-ignore-<说明>"`；
  转场叠化中的重叠只记 warn。
- 渲染后：`python <skill>/scripts/sample_frames.py <成片或场景视频> --timeline timeline/<unit>.json [--scene <场景>.tsx] -o <输出目录>`：
  每拍 5 帧全分辨率 + 一行一拍的联系表，以及每拍**真实的最长定格**（freezedetect；≥ 3s 记 warn，≥ 6s 记 error）。
  lint 的“静止占比”只是静态估算，看不出“动画 0.5 秒做完、剩下 6 秒静止”，以这里的实测为准。
  `--qa` 覆盖不到 Manim 段，Manim 段的文字仍靠这些全分辨率帧人工核对。

### 7. 审查与多轮迭代（rounds/<unit>/rN/）

完整清单、每轮流程和报告模板见 `references/review-rubric.md`。每轮做四道审查，缺一不可：

1. **忠实审（正向）**：拿 inventory 对成片，P0/P1 要点逐条打勾；数字、例子、图的读法和原文一致；
   没有原文之外的论断（引申必须标注）。
2. **反查原文（反向）**：反过来拿原文对成片，逐段读这个单元覆盖的原文页（含图、图注、侧栏、脚注），
   找成片里没有、**清单里也没有**的内容。正向审只能查出“清单有、成片没有”，清单本身的遗漏只有这一道能发现。
   查到的先补进 inventory（标注“rN 补”）并定级，再按级别处理。
3. **语义审**：逐拍对照“画面在说什么”和“旁白在说什么”——静音只看画面会得出什么结论？会不会和旁白相反？
   标签、颜色、箭头方向是否和概念一致？新手会不会学错？
4. **观感审**：lint 门槛（见下表）、节奏、叙事顺序、有没有重复的收尾句；最后做一次**新手测试**：
   让没读过这一章的人（或者另开一个没有上下文的 agent 会话，只给它旁白和抽帧）回答设计阶段写的学习目标问题。

问题分级：**P0 讲错或误导**（必须修）、**P1 缺漏或明显影响理解**（应修）、**P2 观感瑕疵**（顺手修）。

**每一轮怎么走：**

1. 建快照目录 `rounds/<unit>/rN/`，放入本轮的 beats.md、timeline.json、成片、`sample_frames.py` 的联系表与定格表、lint 输出和 QA 汇总（`qa_chapter.py … --md rounds/<unit>/rN/qa.md`）。
2. 做四道审查，写 `review.md`。从 r2 起，开头先写**与上一轮的对比**：改了什么；上一轮的问题哪些修掉了、哪些还在；有没有新冒出来的问题。
   修改不能引入新问题，所以上一轮已经通过的检查项也要重跑。
3. 还有 P0 或 P1：修改 inventory、分镜、代码，生成 r(N+1)，回到第 1 步。
4. 没有 P0 和 P1：把本轮成片、联系表、review 摘要和“与上一轮的差异”交给用户看。
   用户的反馈原样记进 review.md 的“用户反馈”一节，逐条分级（用户明确要求改的至少算 P1）、写好修法，
   按反馈修改后生成 r(N+1)，回到第 1 步。
5. 用户确认满意、不再要求修改：写 `rounds/<unit>/FINAL`（定稿轮次、日期、用户确认的原话），这个单元定稿。

已经存好的轮次目录不再修改，任何修改都进入下一轮；需要回退时，从对应轮次的快照恢复。

## 质量门槛

| 指标 | 门槛 | 谁来查 |
|---|---|---|
| 文字卡时长占比 | ≤ 15% | lint |
| 非卡片场景静止占比（空拍或字面量等待 / 场景时长） | ≤ 40% | lint（静态估算） |
| 文字宽度 | 不超出安全区（1280 宽画布左右各留 60px） | lint |
| 文字卡行数 | ≤ 3 行 | lint |
| 并行补间同属性冲突 | 0 | lint |
| 画面和旁白里的书页、图号、“书里/原图”、内部编号 | 0 | lint |
| 两份时间轴拷贝 | 一致 | lint `--timeline-dir` |
| 文字被压、被线穿过、骑在图形边上、互叠、出画；标签先于对象出现；动画超过旁白 | 0 个 error | `qa_chapter.py`（逐场景 `render.mjs --qa`） |
| 动画做完后一拍里的静止时长（idle） | < 6s（3–6s 为 warn，要说得出理由） | `qa_chapter.py` |
| 每拍最长定格（画面整体实测） | < 6s（≥ 3s 要说明理由；对小物体的慢移动不敏感，以 idle 为准） | `sample_frames.py` |
| 配音疑似重复/多读 | 0 | `audio_timeline.py` |
| P0 要点 | 100% 有画面动作 |
| 原文的图 | 100% 看过图本身、有处置；处置为重画 / 改编 / 换画面的，成片里找得到 | 忠实审、反查原文 |
| 单元长度 | 3–6 分钟，每个单元能独立看懂 |

## 不要做的事

- 不要为了“覆盖”加文字卡：缺了一条要点，先问它该进旁白还是该进画面。
- 不要追加补丁段：要么重写这个单元的叙事，要么把内容编织进已有的拍。
- 不要按模板给固定时长：时长由旁白决定。
- 不要把工作备注、页码指引放上画面。
- 不要在旁白或画面里引用书的页码、图号、“书里/原图/原表/Part”这类说法：动画要自包含，观众没有书也能看懂。只说内容本身，例如“来看这张图”“来看这张表”。
- 不要把内部编号（学习单元编号、内部代号）放上画面或念进旁白：观众不知道那是什么意思。标题只用中文标题。
- 不要把原书没有的数字或公式当作书的内容；示意模型也不要用错数学术语（例如说 1/(1−ρ) 有“拐点”）。
- 不要在一张图里混用两种坐标语义；要变换，就用动画把变换演出来。
- 不要按绝对坐标把标签摆在会长大、会移动的图形旁边，也不要借用别的组的坐标摆标签：用 `attach`。
- 不要自己写 shell 拿锁、放锁，也不要手动删锁目录：用 `render.mjs` 自带的锁和 `render_lock.py run`（`render_lock.py status` 看锁在谁手里）。
- 不要为了让 QA 报告变干净而调大阈值；规则要改，先在 `qa-fixtures` 里加复现用例、跑 `qa_selftest.py`（见 `references/qa-rules.md` 第 6 节）。
- 不要只照着清单或分镜生成，也不要只拿清单审查：生成和审查都要回到原文。
- 不要只读图注就画图：图里的读法、数字、标注要看图本身。也不要把原书的图截图贴进画面：一律重画
  （风格统一、能拆开做成动画，也避开版权问题）。
- 不要覆盖或修改已经存好的轮次产物；不要在用户确认之前宣布定稿。
